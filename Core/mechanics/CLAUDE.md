# Mechanics — how the machine works

*True plumbing: the mechanical workings of the system and the tools.*

Reach for these when you're stuck on tooling or need to do a mechanical thing.

## Gravity rule — plumbing only

This is the folder most at risk of becoming a junk drawer ("stuff about tooling"). The bar: a doc lands here **only if it answers "how does the tooling / file-layer mechanically work?"** A way of seeing → `lenses/`. A way of working → `practice/`. The ground → `foundations/`. When in doubt, it does NOT belong here.

## Holds

**The setup guides** (`setup-mac.md` · `setup-windows.md`, which also covers Linux): getting the system running, once: up to the folder being open, then together in it with the AI. After day one you'll reach for the docs below instead.

YAML frontmatter, markdown conventions, symlinks, hooks, archiving, how rules + skills are written (`rules.md`, `skills.md`), file recovery, auto-memory setup (`memory-setup.md` — the wiring behind `Core/auto-memory/`, and where to look when it isn't loading), and Claude Code usage (native features + troubleshooting).

*Rule-writing* depth is in `rules.md` (rule anatomy, `paths:` scoping, rule-vs-skill by fire-condition); *skill-writing* in `skills.md` (peers, alongside `hooks.md`). The *when/whether to codify* judgment lives in `Core/rules/codification.md` (which points here for the how).

## Reach for this when

Setting up or syncing tooling · something broke · writing frontmatter · archiving · understanding what a hook does.
